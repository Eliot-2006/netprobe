# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Static, self-contained HTML generated by the C++ CLI (`src/report/html_report.cpp`). Inline CSS and
inline SVG only; no JavaScript framework, no external requests (PRD 8.2).

## Users

Engineers triaging a real packet capture (confirmed by the owner). They open the report after
`netprobe analyze` to find out what is wrong or unusual: truncated or corrupt captures, decode errors,
TCP streams with missing bytes, the heaviest flows and talkers. Portfolio reviewers also open the demo
report, but the report is designed for the engineer's triage job.

## Product Purpose

NetProbe is an offline analyzer for classic PCAP files: bounds-checked zero-copy decoding of
Ethernet/VLAN/IPv4/IPv6/TCP/UDP, TCP stream reassembly with explicit gap, overlap and retransmission
accounting, and deterministic JSON/HTML reports. Success for the report: an engineer can tell within
seconds whether the capture is trustworthy and where the problems are, then drill into exact numbers.

## Positioning

Every number is exact and reproducible (deterministic output, bounded detail lists over exact
aggregates). The report says precisely which byte ranges of which streams are missing and whether
the receiver acknowledged them (capture loss vs. unsent data), which typical summary tools do not.

## Capabilities and Constraints

- One file per run, opened locally or attached to a ticket; must work offline and in any browser.
- Content comes only from the analysis model: capture info, decode counters by (kind, layer, reason),
  timeline buckets, flow outcomes, top flows, incomplete streams with gap lists, talkers, services,
  reassembly totals, run details (omitted with `--deterministic`).
- Size budget ≤ 2 MiB at 1000 flows; all dynamic text HTML-escaped.
- Service names are port heuristics and must be labeled as such.

## Evidence on Hand

Real sample captures and fixtures in `samples/` and `tests/fixtures/`. No customer data,
testimonials or benchmarks may be invented; performance figures appear only from measured runs.

## Product Principles

1. Trust first: capture integrity and warnings come before anything else.
2. Exact over approximate: show real counts and byte offsets; mark heuristics and limits.
3. Scannable under pressure: tables and labels an engineer can skim, not prose.
4. Self-contained and safe: no network, no scripts required, every value escaped.

## Accessibility & Inclusion

WCAG 2.1 AA contrast in light and dark schemes; semantic tables with header scope; SVG charts
carry text alternatives; usable at 375 px width.
